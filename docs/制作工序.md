# 《The Last Rule》西雅图地图 · AI 协作制作工序 v1.0

> 技术栈：Three.js（WebGPURenderer + TSL 着色语言）
> 视觉目标：对标《最后生还者 第二部》的氛围与质感
> 配套文档：[西雅图地图设计规范.md](西雅图地图设计规范.md)

## 0. 开工前必须先对齐的三件事

### 0.1 "2D 俯视角"与"TLOU2 画质"有冲突

TLOU2 的质感来自 3D 光照：体积雾、潮湿反光、植被透光、室内外明暗对比。纯 2D 贴图画不出你给的参考图里的效果。

**建议的解法**：场景用 **3D 制作**，摄像机采用**固定高角度俯视**（参考《暗黑破坏神 IV》《全境封锁》的俯视镜头）。

- 玩法上仍然是俯视角沙盒，和僵尸毁灭工程、RobRun 一致
- 视觉上拥有完整的 3D 光照、阴影和雾
- 俯视镜头看不到远景和天空，**反而大幅降低制作量**（远景 LOD、天际线都不用精做）
- 室内采用"屋顶淡出 / 剖切"显示

### 0.2 AI 能做什么，不能做什么

| 我擅长（可以直接交付） | 我做不好或做不了（需要你或外部资源） |
|------|------|
| 引擎架构、渲染管线、WebGPU / TSL 着色器 | 高质量 3D 模型雕刻（主角级建筑、载具、丧尸） |
| 程序化生成：地形、路网、建筑拼装、植被散布 | 手绘或扫描级贴图 |
| 地图数据结构、规则校验（连通性、通行性） | 角色动画 |
| 材质系统：潮湿、苔藓覆盖、污渍、积水 | **"好不好看"的最终判断**——这必须由你来做 |
| 规则化场景布置（残骸、路障、杂物） | 生成的图片不能直接作为贴图，只能作概念参考 |
| 调试工具、浏览器内关卡编辑器、性能优化 | |
| 用浏览器截图自查后再交给你审 | |

**美术资产来源**（第 0 步需要你决定）：
- Poly Haven（CC0，免费，量少但质量高）
- Fab / Quixel Megascans（扫描资产，质量最接近 TLOU2）
- 购买模块化城市套件（Synty 风格太卡通，需选写实系）
- AI 3D 生成工具（Meshy、Tripo、混元3D 等）：只适合小道具，不适合主体建筑
- 外包或自制主角资产（太空针塔、裂解塔等地标）

### 0.3 期望校准

TLOU2 是数百名美术制作、大量烘焙光照、逐场景手工打磨的 3A 线性关卡。浏览器里运行的 4km 开放沙盒，在当前技术下可以达到的目标是：

> **氛围对标**：色调、光影、雾、潮湿感、植被侵蚀、杂物密度达到"一眼看出是 TLOU 味道"；
> 而不是**资产精度对标**（每一块砖的雕刻细节）。

这个目标要在第 3 阶段（垂直切片）结束时，用**并排截图对比**来验收，而不是凭感觉。

## 1. 总体原则

1. **先窄后宽**：先把**一个 150m×150m 的街区**做到最终品质（垂直切片），验收通过后才铺开全城。这是避免"做了一整座城才发现不好看"的唯一办法。
2. **数据与代码分离**：地图布局全部存成 JSON 数据，你可以直接改数据而不用找我改代码；我写的生成器读取数据产出场景。
3. **每一步都有可运行的产物**：每步交付一个能在浏览器打开的页面 + 截图，不交付"半成品代码"。
4. **先文档后代码**：每一步开始前我先给一份很短的"本步方案"（几百字，token 便宜），你确认后我再写代码（token 贵）。
5. **每一步都有固定验收清单**：通过才进下一步，不通过就在本步内迭代。
6. **进度落盘**：每步结束更新 `PROGRESS.md`，记录已完成内容、决策、遗留问题。换新对话时我读这一个文件就能接上，不用重读全部代码。
7. **建议用 git 管理**：每步验收后提交一次，不满意可以随时回退。（目前项目目录还不是 git 仓库。）

## 2. 工序总览

| 阶段 | 名称 | 核心问题 | 产物 | Token 消耗 |
|------|------|---------|------|-----------|
| **P0** | 技术与视觉预研 | 浏览器能不能跑出 TLOU 的感觉？ | 技术验证页 + 氛围样板间 | 中 |
| **P1** | 2D 数据层 | 地图布局对不对？ | 浏览器内 2D 地图查看器 + 校验报告 | 低 |
| **P2** | 3D 白盒 | 尺度、路线、手感对不对？ | 可开车、可走路的灰色方块城市 | 中 |
| **P3** | 垂直切片 | 最终品质能不能达标？ | 一个街区做到最终画质 | **高** |

### P0 · 技术与视觉预研

#### P0.1 项目脚手架与技术验证

- **目标**：确认 WebGPU 渲染管线在你的目标硬件上能跑起来，摸清性能上限。
- **我做**：Vite + Three.js（WebGPURenderer）项目骨架；一个测试场景，包含 PBR 材质、级联阴影、高度雾、后处理（GTAO 环境光遮蔽、Bloom、色彩分级 LUT）、1 万株实例化植被；屏幕上显示 FPS 和显存占用。
- **你提供**：目标硬件（最低配置显卡是什么？是否需要支持不支持 WebGPU 的浏览器回退到 WebGL？）。
- **交付物**：`npm run dev` 可打开的测试页。
- **验收**：在你的目标机器上 ≥ 60 FPS（或你定的帧率）；各项效果都能开关对比。

#### P0.2 视觉目标板

- **目标**：把"TLOU2 的感觉"拆解成可测量的参数。
- **我做**：分析你的 5 张参考图 + 你补充的参考，产出一页《视觉目标说明》：色板（取色值）、光照方向与色温、雾的浓度与颜色、潮湿程度、植被覆盖率、杂物密度、室内亮度范围。并指定一个**俯视角**下的构图参考（因为你的参考图都是第三人称近景，俯视下的观感会不同）。
- **你提供**：补充 3–5 张你认为"俯视角下也应该是这个感觉"的参考（可以是其他游戏的俯视截图、航拍废墟照片）。
- **交付物**：`docs/视觉目标.md`。
- **验收**：你确认"就是这个方向"。

#### P0.3 氛围样板间 ⛳ Gate 1

- **目标**：用最少的资产，证明浏览器里能做出 TLOU 的氛围。
- **我做**：用 Poly Haven 等免费资产搭一个约 40m×40m 的街角：一栋带破窗的建筑、积水路面、一辆锈车、爬墙藤蔓、灌木、阴天光照、雾。俯视镜头 + 可切换近景镜头。之后反复调光照、材质、后处理参数。
- **你提供**：每轮截图的反馈（"太亮""不够湿""绿得太假"这类即可）。
- **交付物**：样板间页面 + 与参考图的并排对比截图。
- **验收**：并排对比下，你认为氛围已达到可接受水平。**如果这一步达不到，说明需要调整资产来源或视觉目标，必须在这里解决，不能带到后面。**

---

### P1 · 2D 数据层（最便宜的迭代阶段，尽量在这里改设计）

#### P1.1 地图数据结构

- **我做**：定义地图 JSON 格式（区格、水域多边形、高程、道路图、地块、POI、营地、控制节点），以及数据校验器。
- **交付物**：`data/schema` + 一份字段说明。
- **验收**：你确认这个结构能表达设计规范里的所有要素。

#### P1.2 宏观地形

- **我做**：按浓缩后的西雅图绘制海岸线、运河、联合湖、华盛顿湖、杜瓦米什水道的多边形，以及丘陵高程图；做一个浏览器内的 2D 地图查看器（可缩放、可开关图层）。
- **验收**：你一眼能认出是西雅图；水系切割关系符合设计规范第 1 章。

#### P1.3 路网

- **我做**：生成 L1–L5 道路图、10 座桥及其状态；查看器中按等级着色。并编写**自动校验**：
  - 每个 C1 营地开车可达
  - 每个 T1 周边 250m 内没有车道直通
  - 任何时候至少有 2 条南北向汽车通路
  - 每个大区格内有一条贯通的摩托车路线
- **验收**：校验全部通过；你在查看器上模拟几条跑图路线，觉得合理。

#### P1.4 地块与 POI 布置

- **我做**：由路网切出街区地块，按区域类型分配建筑用途；放置 T1–T4、营地、控制节点、中立区；叠加丧尸密度热力图层。
- **验收**：对照设计规范第 2–4 章的分布规则全部满足；危险梯度在热力图上一目了然。

---

### P2 · 3D 白盒（验证尺度与玩法） ⛳ Gate 2

#### P2.1 白盒生成

- **我做**：从 P1 的数据自动生成 3D 场景：地形网格、道路、灰色方块建筑（按区域给高度）、水面、桥梁、路障方块。只用纯色材质，不做美术。
- **验收**：整座城可加载；俯视镜头下布局清晰。

#### P2.2 角色与载具原型

- **我做**：接入物理引擎（Rapier）；胶囊体角色；简易汽车和摩托车（加速、转向、坡度影响）；按设计规范 5.2 的缝隙宽度建立分载具碰撞层。
- **验收**：汽车过不去的缝摩托能过；阶梯摩托上不去；T1 外围确实只能下车步行。

#### P2.3 玩法度量

- **我做**：调试面板（显示当前道路等级、区格、危险等级）；跑图计时工具；噪音半径可视化。
- **验收**：驾车横穿全图约 3–5 分钟；营地到最近 T2 的往返时间合理；**你亲自开车跑一圈，觉得尺度对了**。尺度问题一旦进入美术阶段就极难修改，必须在这里定死。

---

### P3 · 垂直切片（决定项目上限的阶段） ⛳ Gate 3

**建议选址**：派克市场到滨海水族馆之间的一个约 150m×150m 区域。它同时包含：街道 + 一栋可进入的室内 + 积水/水域 + 高低差 + 车辆路障，几乎覆盖了全城所有的视觉问题。（也可以换成煤气厂营地或港湾医疗中心，由你决定。）

#### P3.1 模块化建筑套件规范

- **我做**：定义建筑模块的网格尺寸（如层高 3.5m、墙段宽 2m）、拼接规则、命名规则；列出切片需要的最少模块清单（墙、窗、转角、门、屋顶、楼梯、残破变体）。
- **你提供**：按清单采购、生成或制作资产（这一步是我最无法替代你的地方）。
- **验收**：模块能无缝拼出一栋 4 层的废弃楼。

#### P3.2 材质系统

- **我做**：用 TSL 编写分层材质：
  - 世界空间顶部投影的苔藓/泥土覆盖（让所有朝上的面自动长苔）
  - 潮湿度：降低粗糙度、加深颜色、地面积水坑
  - 雨痕、锈迹、水渍等贴花
  - 顶点色控制的污渍混合
- **验收**：同一个灰色模块，套上材质后能呈现"废弃 20 年"的感觉。

#### P3.3 植被

- **我做**：实例化草、蕨类、灌木、针叶树；墙面藤蔓（沿建筑表面生成）；风动着色器；按规则自动散布（裂缝、墙根、屋顶）。
- **验收**：参考图 4 的"自然吞噬城市"感觉成立。

#### P3.4 光照与大气

- **我做**：阴天天光、体积雾、环境光遮蔽、反射探针、室内外曝光过渡、色彩分级；手电筒与室内黑暗处理（参考图 3、5）。
- **验收**：与 P0.3 的样板间一致或更好。

#### P3.5 场景布置

- **我做**：规则化散布杂物（碎纸、碎玻璃、垃圾袋、残骸车）；路障组件；可读的"通行语言"符号（红 X、铁丝网、粉笔箭头）；少量叙事小场景（尸体、失败的路障、求救字迹）。
- **验收**：密度对标参考图 1；通行符号与碰撞 100% 一致。

#### P3.6 室内

- **我做**：一栋可进入建筑：屋顶淡出、室内黑暗与手电、积水地面（参考图 3）。
- **验收**：室内与室外切换自然，俯视镜头下室内可读。

**Gate 3 验收**：切片在目标硬件上达到帧率要求；与参考图并排截图，你签字认可。**这个切片的品质就是全城的品质上限，之后只是复制。**

### P4 · 生产管线（把切片变成可批量复制的流程）

| 步骤 | 内容 |
|------|------|
| P4.1 | 程序化建筑生成器：读取地块数据 + 区域风格，自动拼装模块化建筑 |
| P4.2 | 规则化布置器：自动散布植被、杂物、残骸车、路障 |
| P4.3 | 浏览器内关卡编辑器：在生成结果上手动调整、放置手工资产，修改回存到 JSON |
| P4.4 | 流式加载：按 32m 区块加载/卸载，LOD，远处建筑用简化模型 |
| P4.5 | 性能预算：每个区块的三角面、绘制调用、显存上限，超标自动报警 |

**验收**：用管线**重新生成**一遍 P3 的切片区域，结果品质不低于手工版本。

### P5 · 区域铺开

**原则**：一次只做一个区域。每个区域走同样的小循环：

> 数据微调 → 自动生成 → 手工打磨地标/POI → 截图审查 → 提交

**建议顺序**（从难到易，尽早暴露问题）：

1. 市中心核心区（C4–D6：太空针、派克市场、先锋广场）——最密集，最考验性能
2. 南部高危区（港口、流明球场、SODO）
3. 第一山与港湾医疗中心
4. 北岸营地带（煤气厂、红场、巴拉德、弗里蒙特）
5. 联合湖与桥梁
6. 外围住宅区与新手区——最简单，大量依赖程序化生成

**T1 地标**（太空针、球场、医疗中心）需要单独手工制作主体资产，建议与区域铺开并行安排。

## 4. 每一步的协作流程

```
你：开始 Px.y
 ↓
我：给出本步方案（几百字：做什么、怎么做、需要你提供什么）
 ↓
你：确认 / 修改方案            ← 在这里改最便宜
 ↓
我：实现 → 自己用浏览器打开截图自查 → 修到满足验收清单
 ↓
我：交付（可运行页面 + 截图 + 改动说明），更新 PROGRESS.md
 ↓
你：审查 → 通过（提交 git）/ 提出修改（在本步内迭代）
```

**省 token 的习惯**：
- 每步开一个新对话或在长对话后压缩；我依靠 `PROGRESS.md` 和设计文档接续
- 反馈尽量具体到画面（截图圈出来 + 一句话），比"感觉不对"更省迭代轮数
- 参数类调整（雾浓度、颜色、密度）我会做成调试面板上的滑条，你自己拖到满意后把数值告诉我，不需要我反复改代码

1. **镜头**：是否接受"3D 场景 + 固定高角度俯视镜头"的方案？俯仰角大约多少（偏 45° 斜俯视，还是接近 70° 的顶视）？

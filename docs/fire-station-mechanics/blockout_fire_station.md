# 消防站 · 围困后的工坊订单
## 给搭建、脚本与测试的设计规格

玩家进东侧前厅，隔着接待窗看到值班记录，透过固定观察窗可辨认维修间双表盘。读记录、核对架号就能做侦察委托。继续启动试验台则把一个安静的信息差变成可被别人听见的搬运任务。泵运到南坪后，玩家仍要自行离开街区；回营实际安装才形成长期工程贡献。资料目标是 M0–M3 设计交接，M4 以下为施工输入。

[分区与线路图](station-design.svg) · [机制清单](level_fire_station.jsonc) · [验收记录](acceptance_fire_station.md)。图为平面设计投影，门洞、转角和分区按本版说明放样，运行实测另列。现有消防站试玩页有其他版本的交互，不能为这一版提供验收证据。

### 体量与安装

原点取站房中心，X 向东、Z 向南、Y 向上，以完成面为标高。站房边界 X ±16、Z ±12 m。北侧是归队后场，南侧是出车坪，西侧是回车道，东侧才是公众入口。西厅两辆车各自面对同轴的南北车门；车尾与西侧车道均不作固定储物带。水带车停在东侧地面带，离开泊位不占消防车位。中带北端是维修间，其南侧为污装、洗消、更衣、穿戴。东翼由北向南安排餐厨、起居、宿舍与接待。公众通行止于接待窗，固定观察窗继续传递维修间标识；值班人员经侧门接入员工廊。归队人员从车厅进污装间、经过洗消后才有通往清洁走廊的日常出口。厨房破口只改生活翼内部连通。

现有项目可引用 bench、board、truck、ambulance 等放置件表意；IN、DR、MV 是研究分类。消防泵、制动推车和试压表的完整可玩 prefab 均待资产验明。原型使用盒、圆柱与斜面组合，正式资产需登记具体 prefab ID。保存后以稳定放置 ID 对照所有宿主，抽查推车四角与中心、旋转/制动前后、门槛和台阶收口；重载后对比 transform、可见体积、触点和碰撞。以上均是 ART-SNAP-01–04 的施工和验收依据。

### 状态、失败与结算

每份订单按“订单 ID + 泵序号”登记。换泵清除该工位上次测试进度，已辨认的序号与设备故障信息保留。试验由现场试验装置维持，手摇电源只改善终端记录；缺少发电装备仍可完成基本委托。坏泵试验结束只记录故障，不能提交合格件。试验中断不得出现合格章，重新测试会再次产生可听事件。玩家手动激活的声音只进入本局声音系统，实际感染者响应随场景状态变化。

推车停放后才能装载；移动需要松开制动和空出双手。松手先停住车，再恢复玩家动作；物资留在该车绑定位置，其他玩家可以接手。多人同时争抢只允许一次占用。卷门在当前货物包络仍占据门洞时保持或回退至安全位置。卸载、放弃、失去工具和离开站房都保留人员返路。

| 玩家结束方式 | 当下结算 | 可恢复项 |
|---|---|---|
| 只带普通设备情报成功撤离 | 提交侦察委托。受保护的小件情报与任务凭据分别登记 | 取得情报无需开卷门、验泵或上交货物 |
| 泵已交接，人仍在局中 | 运单只记待结算，站内离场不授予契约收益 | 交接重放按同一订单查询，禁止重复生成库存 |
| 交接后成功撤离 | 同一订单一次性记入营地待安装库存，确认运输贡献 | 有材料并实际完成安装后才修复工坊，授予工程贡献 |
| 队伍弃车或角色死亡 | 适用进入方式的死亡规则；关键泵、任务凭据都不能存入 2×2 安全箱 | 未完成的契约不发收益，已安全存入的小件情报按 GDD 保留；工坊原等级和地块所有权不受此订单失败影响 |

北门是人员离站口。侦察声望或当局线索解锁后段隐蔽撤离资格；未解锁仍可走普通街区出口。V0 的最后步行段属于街区撤离接口。南坪接驳点只接货。车辆无法在接驳点跳过步行段完成整局结算。

### 制作与移交

先做无贴图的可玩梗概，验证进前厅—识别焦点—接货/弃货—返回，再用最终角色、相机、载具走位。保持东入口第一眼的前厅、接待窗和泵台标识。概念画师依据验证后的体块做 paintover；环境美术接收宿主清单，音频接收泵台及卷门的可中断事件，灯光突出门斗、表盘和离站口。未完成 M5 时拓扑保留可修改状态。早期图中的北侧车门阻塞、货梯误读、把站内离场当撤离均由本设计纠正。

其他卷门和人员门按实际轮廓通行。④控制南坪订单装载桥的对接，货物推到别处不触发卸货。车辆大厅始终有人员绕路。

M4 的五分钟是无对抗的关键走位短测；完整 POI 的情绪曲线包含自选搜查、检验、等待、搬运与离站，按 15–20 分钟组织。两者分表计时。

# 消防站机制验收记录

审查对象为本目录的机制清单、施工规格和玩法布局。复现规格检查可在项目根目录运行：

```sh
node tools/fire-station-mechanism-check.mjs
```

## 证据与门禁

静态检查读取 JSON 中的机制卡、路径边、里程样本、掩体表和预算，并从美术 RAG 的交互物表独立读取原型分类 ID。预算为设计配额，图边为预定通路，断点为设计里程，类别 ID 不证明引擎里已有相应成品。引擎运行、无 UI 阅读、声音响应、货件结算、子弹遮挡及多人行为分别按下述协议采集。既有站点试玩中的旧运输任务不能提供本次改版的测量数据。

M4 目标为用正式胶囊、相机和载具在 5 分钟内走完主线，三条路可走且零卡死。M5 使用同一记录了构建号、常量清单版本和场景存档的构建。M6 所需的布局冻结、运行时预算与交接签字待 M4、M5 通过后办理。阻断项未关闭时不给整关“通过”结论。

## M5 盲测协议

招募 12 名第一次接触本关的测试者。每人单独测试同一构建，关闭路线指示与交互高亮，主持人只告知初始委托和已有操作。全程静默观察，结束后问“你刚才看见什么、为什么停下”。同一人在同一轮仅计一次，AI 评审和开发者自测单独记录。固定种子保存事件状态与局部声音开关。H2 用安全测试遭遇，隔离外来 AI、玩家与伤害。记录真实测试人数、退出和异常，分母事先确定，不挑选成功样本。

| 项 | 采样与判定规则 | 状态 |
|---|---|---|
| H1 空间导航 | 入口 10 s 内首次朝向与事先标定目标的夹角 ≤45°，且说明来自空间线索。至少 10/12 达标；每处停留超过 15 s 记录时间、位置、朝向、理由。入口到焦点另记 90–150 s 目标。 | 0/12 已测 |
| H2 空威胁 | 记录首次无提示蹲下、瞄准或贴墙，排除脚本强制姿态和载入前动作。至少 5/12 主动反应，核对该区 AI 次数、玩家伤害次数和安全退路。 | 0/12 已测 |
| H3 线索乱序 | 随机分配初始线索，每种起点有人体验；12/12 能从最后发现点在 90 s 内回主线。记录拾取顺序、重复证据是否重复结算；百次图模拟另记。 | 0/12 已测 |
| H4 失败前进 | 分配试泵中断、弃车与出口受阻场景；记录测试者是否能自行找到至少一条退路、选择所需时间及其空间依据。各人能自行脱身，无被困复现。 | 0/12 已测 |
| H5 撤离可读 | 在最后一个观景点停一次，先让玩家指出撤离方向，再实际走到选定接口；记录候选位、所指地标与是否误认货物接驳车为玩家撤离。 | 0/12 已测 |

每个样本登记「构建 / 匿名受试 ID / 入局模式与负重 / 事件种子 / 测试编号 / 触发时刻 / 位置与朝向 / 首次选择 / 回撤或放弃原因 / 结果 / 录像或事件日志编号」。同时登记退出意愿，不设及格线。每 2–3 周复测；保留初见组作盲测，复玩组只用于回归测试。

## 关键分支与异常结算回归

- 纸面交接和实物编号应支撑无电轻装路线。验证工具丢失、断电和泵试验取消后的可退状态。
- 依次测试泵达标、中途放弃和错选分支；记录噪声事件与区域响应，区分扰动导致的感染者和空威胁安全域。
- 空车制动、空车移动、装泵、断线、抢占、弃车和再接管逐一覆盖。验货状态、泵实例占用者、库存唯一数应一致；双人同时提交同一货件时只准一次有效提交。
- 只有货物交接、个人撤离、对应营地行为分别完成时才执行相应结算；测普通情报安全箱准入、关键泵拒绝入箱、撤离前死亡和营地安装重试。对照 GDD 的轻装派遣/武装突袭损失规则。
- 按 ART-SNAP-01–04 检查门框与门扇封闭、活动装置全行程、货车松闸后的附属件、存档重载。测量记录分列“研究参考 / 设计采用 / 实测 / 资产与构建版本”。

## 静态复核记录

1. 第一轮发现两张诱导卡参数同为空，触发“同一机制族第二次须换参数”的自动拒绝。修订为纸面线索组合与工具供电解读两种可测试条件，重新运行检查通过。
2. 交叉比对后发现破口借用了双开门分类。改用残墙低掩体类别描述实体支撑，同时以通行卡记录净宽和落点。目录检查与空间语义复核通过。
3. 将整条路线从“自报三条边不相交”改为逐条给出见证并校验：15 个节点、21 条物理边；逐次删除任意一边均可达全部节点。三条见证路径按无向物理边去重，即使反方向使用同一门洞也不能重复记数。
4. 对线索指向做独立复查。以交班册、轮迹、泵架签任意顺序拾取，按已登记 1.6 m/s 模型计算回主线的最短步行时间；固定种子 100 组包含 6 种顺序，100/100 生效，最慢 22.5 s。该值不含观察、读表、互动、排障或战斗。
5. 最终运行规格校验器，手册 §4.2 全部 12 条、A1–A7 的设计数据及两组补充检查通过。M4 实际寻路与性能、M5 五项盲测仍无本版构建记录。手册 §5.3 的整关通过条件当前尚未触发。
6. 逆向试验逐次只改变一项并从标准输入提交给同一校验器：删去提示、重用路径边、把掩体改为 1.30 m、截短断点采样、将撤离末段改为 V2、改错线索指向、将预算改为 350,001。七个副本全部在对应项报错，正式清单保持原值。

## 订单状态复审

运行 `node tools/fire-station-order-review.mjs` 可重演七个设计用例。模型在内存中依次处理交互动作，检验普通情报保护、关键货物拒绝入箱、试验中断与换泵、推车接管、卷门防夹与接驳桥、幂等交付与安装、交货后阵亡的结算。两次修订分别把停在门槛上的货车位置独立于持车者、把交货条件改为指定桥位对接；另门绕到南坪依然可以对接交货。七例均通过。网络并发、掉线恢复、实际背包与营地库存仍需联机构建回归。

图面复审已补上东侧门斗、北侧人员出口、污装区至清洁走廊的门洞，以及三条不同方向的泵台接近线。平面上的路线与图结构可以复查。M4 在实际体块上重点量入口至泵台的可视性、维修平台落点、载货转向包络与门槛。
## 首版可玩白盒 · 浏览器走位记录

验证入口为 station.html，使用 Three.js 透视场景。通过浏览器实际发送 Shift + W，角色从东侧 X 22.0、Z 9.0 经门斗跑到前厅 X 14.7、Z 9.0；空格起跳采得脚底离地 0.31 m（单帧采样）。N 显示连续步行路径，R 返回米制首个命中距离，M 能切换全站俯视。本次观察未出现页面脚本错误。

读取当前场景的实际网格、可见状态和行走函数，另做以下检查：

- 渲染场景中半开卷门拒绝站立、允许蹲姿；抬门后站姿可通。破坏箱可被 Raycaster 命中，隐藏后同位置解除遮挡与行走阻塞。
- 沿维修通道逐步跨过两侧踏步，支撑面峰值 0.84 m；从出生点对维修间、车厅步带、厨房破口、北出口独立求路，四处均返回连续路径。
- 保存放置件 126 个通过宿主与安装基准检查。图模型回归和订单模型回归独立运行。

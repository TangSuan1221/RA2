## 0. 给执行 AI 的边界

### 0.1 你产出什么（三件套，缺一不算交付）

1. **机制清单** `level_<id>.jsonc` —— 本文 §4 的契约，机器可校验。
2. **白盒规格** `blockout_<id>.md` —— 体块、尺寸、锚点、路径图、视线断点，人能照着搭。
3. **验收报告** `acceptance_<id>.md` —— §5 的机器项 + 人判项逐条给结论，不给"感觉不错"。

### 0.2 你不产出什么

- 不写渲染、不写战斗管线、不改 `00–13` 任何章节（那些是既成契约）。
- 不定武器伤害、护甲减伤、弹药系数（`08 §7` 明确归数值侧）。
- 不"顺手"新增美术资产；只允许引用已有 prefab 清单里的 ID。
- 不写剧情台词；只写"这里需要一次对白触发"，交给叙事。

### 0.3 八条硬规则（违反即返工）

| # | 规则 | 理由 |
|---|---|---|
| R1 | 每条机制必须能写成**一句可判定的断言**；写不出就删掉 | 不可判定的设计 = 未来的返工 |
| R2 | 数值只能引用常量 ID；没有就登记 `LV-新增-*` 并给校准法 | 防止第 3 天分不清是设计错还是数值错 |
| R3 | 所有参数标 **E1/E2/E3**；E3 必须带校准方法 | 顽皮狗没公开过米数，别把估算当官方 |
| R4 | 禁用"手感好、有趣、沉浸、爽"作为验收词 | 无法复核 |
| R5 | 每次迭代**只改一个变量**，并记录改前/改后 | 否则不知道是哪一处起了作用 |
| R6 | 先做能跑的糙版，再谈美术；blockout 阶段禁止任何贴图级细节 | 见 §7.2 的"扔掉会心疼"红线 |
| R7 | 任何"看起来像掩体"的东西必须真的能挡子弹 | 这是 TLOU2/Uncharted 反复强调的**承诺一致性** |
| R8 | 布局冻结（M6）之后只做打磨，不再改拓扑 | 美术进场后改布局是灾难性返工 |

## 1. 机制的定义：四要素

> **一句话：机制 = 玩家为了一个目标，在可读的空间里，付出一种代价做出的一个动作。**
> 缺任何一项，它就不是机制，是装饰。

| 要素 | 字段 | 回答的问题 | 反例 |
|---|---|---|---|
| **① 动词** | `verb` | 玩家到底做什么？（翻/爬/挤/伏/绕/射/断/等/抬） | "这里有掩体"——玩家没有动词 |
| **② 代价** | `cost` | 做这件事付出什么？（时间/噪声/暴露/资源/不可逆） | 免费通行 = 没有决策 |
| **③ 读法** | `read` | 玩家凭什么**在无 UI 情况下**知道这里能做什么？ | 只有 UI 提示才知道 = 读法缺失 |
| **④ 断言** | `acceptance` | 机器怎么判定它成立？ | "要让人紧张"——无法判定 |

**为什么是这四项**：Evan Hill 讲博物馆时反复强调"清晰的信息 + 玩家是演员"——玩家必须**先读得懂，才演得下去**；Michael Barclay 的掩体规则本质是"承诺一致性"（看起来能挡就得能挡）。四要素是这两条原理的可执行化，属本文的工程归纳（E3）。

### 1.1 一张卡长什么样（以翻窗为例）

```jsonc
{
  "id": "mech_vault_low_07",
  "family": "traversal",
  "verb": "vault",
  "cost": { "type": "exposure", "value": 1.2, "unit": "s" },
  "read": { "channel": "height_band", "telegraph": "sill_0.90m + 磨损漆面", "noUi": true },
  "space": { "prefab": "WINDOW_A_090x120", "entry": [12.4, 0, -3.1], "exit": [12.4, 0, -1.8] },
  "params": { "clearW": 0.90, "sillY": 0.90, "wallThickness": 0.20, "landingDepth": 0.80 },
  "acceptance": [
    "sillY ∈ [CC-STEP-UP, LV-COVER-LOW.max]",
    "landing_clear ≥ 0.80",
    "ai_link === true"
  ]
}
```

## 2. 设计流水线 M0–M6（含门禁）

> **门禁（Gate）的意思是：不过门不许进下一步。** 这是 TLOU2 团队"fail early, fail often"的工程化——把失败限制在最便宜的阶段。

| 阶段 | 时间盒 | 输入 | 动作 | 产出 | **门禁** |
|---|---|---|---|---|---|
| **M0 立项卡** | 0.5 d | 一句 brief | 答六问 | 立项卡 | 六问全答；brief ≤25 字 |
| **M1 三层目标** | 0.5 d | 立项卡 | 叙事/体验/功能三层 | 目标表 | 功能目标必须是**一个可教的动作** |
| **M2 分幕** | 0.5 d | 目标表 | 起承转合 + 情绪曲线 | 幕表 | 曲线有 ≥1 峰值 ≥0.75、≥1 谷值 ≤0.35 |
| **M3 机制清单** | 1 d | 幕表 | 每幕列机制，填四要素 | `level_<id>.jsonc` | 每条四要素齐全 + ≥1 断言 |
| **M4 白盒** | 2 d + 10 d | 机制清单 | 体块 + 走位 | `blockout_<id>.md` | 5 分钟走完主线；3 条路可走；零卡死 |
| **M5 Alpha 测试** | 每 2–3 周 | 白盒 | 不说话递给人玩 | 测试记录 | 盲测 ≥4/5；空威胁 ≥40%；断链 0 |
| **M6 锁定交接** | 1 d | 测试记录 | 冻结布局、交接、预算核对 | 交接包 | 预算达标；交接物齐；拓扑不再改 |

### 2.1 M0：六问（Barclay 版，直接抄）

| 问题 | 回答格式 | 例（市中心） |
|---|---|---|
| Location 地点 | 一句话 | 西雅图市中心，隔离区旧址 |
| Premise / "剃刀" | 一句话主题 | "跟着 Tommy 的踪迹，发现被杀的 WLF 士兵" |
| Major Goals 主目标 | 玩家知道要干什么 | 找到线索链的终点 |
| Affects Gameplay | 定 tempo | 开放、低速、可反复穿行 |
| Mechanics Introduction | 教什么动作 | 骑马穿行 + 攀爬废墟 |
| Exotic Gameplay | 一次性奇观 | 雨中倒塌的银行中庭（可选） |

> 注意：**brief 是别人给的，High Level Goals 是你自己写的。** 这一步是资深与新手的分水岭——brief 只有一句话，目标要能撑起整关。

### 2.2 M1：三层目标

| 层 | 回答 | 博物馆的答案（E1） | 你的答案必须 |
|---|---|---|---|
| 叙事 | 这段完成什么情感任务 | 关系最高点 → 埋下裂痕 | 可被一句台词或一个道具承载 |
| 体验 | 玩家应该有什么感觉 | 无战斗也有吸引力、可快可慢 | 对应一个 tempo 区间 |
| 功能 | 教什么机制 | **正式教游泳**（开场被推下河） | 是一个**动作**，不是一个系统 |

### 2.3 M2：分幕与情绪曲线

- 用**起承转合**拆三幕：设定 / 发展 / 转折与结局。
- 每个小互动内部同样成立（推乔尔下水本身就是一个微型起承转合）。
- 输出 `tempo`（0–1）序列；**曲线必须至少有一次上到 0.75 以上、一次下到 0.35 以下**，否则节奏是平的。

> 你的游戏是沙盒，**不要用三幕结构整张地图**；用它结构**单个 POI / 单次遭遇**：15–20 分钟的 micro-arc（进入 → 发现 → 升级 → 撤离或翻车）。

### 2.4 M3：机制清单

每一幕列 2–5 条机制，逐条填四要素。**一关的机制总数控制在 6–12 条**——超过 12 条，玩家学不会，团队也测不完。

### 2.5 M4：白盒（两段式）

| 子阶段 | 时长 | 做法 | 判断 |
|---|---|---|---|
| **可玩梗概** | **2 天** | 只放最关键体块，能跑通"进入 → 焦点 → 撤离" | 想法站不站得住 |
| **白盒** | 10 天 | 加路径、掩体、锚点；用真实角色/相机/载具走位 | 尺寸对不对、卡不卡 |

- **3D 优先**：不画 2D 草图，直接在 Maya/引擎里搭竖版粗模——垂直度用纸画不出来（E1，Barclay 说他 90% 的关不画 2D）。
- **blockout 只允许三种形体**：盒子、斜面、圆柱。任何"装饰性曲面"都算越界。
- 走位测试必须用**最终胶囊、最终相机、最终载具**；用错胶囊测出来的净宽全是废数。

### 2.6 M5：测试协议（最关键的一步）

> **不说话、不引导、把原型递给对方就走。**（E1，Hill 的做法）

| 观察项 | 记录 | 阈值 |
|---|---|---|
| 迷路点 | 第几秒、停在哪、往哪看 | 单点停留 >15 s 记一次 |
| 首次选择 | 进入 POI 后 10 s 内走向 | 与设计意图夹角 ≤45° 记为命中 |
| 空威胁反应 | 是否无提示蹲下/举枪/贴墙 | ≥40% 测试者触发（E3，12 人校准） |
| 主线路程 | 从入口到焦点耗时 | 目标 90–150 s |
| 退出意愿 | 是否主动往回走/找别的路 | 记录，不做阈值 |

**每 2–3 周一次，全项目范围**（不只是测你这一关）——这样所有人都知道别的关长什么样。

### 2.7 M6：锁定与交接

- 冻结：拓扑、连通性、POI 位置。之后只改材质、光、声、装饰。
- 交接包必须含：机制清单、白盒规格、参考图（概念画师 paintover）、验收报告、已知缺陷清单。
- **一关的 owner 是关卡策划**：第一个进场、最后一个离场；两年做 3–5 关是正常产能。

## 3. 机制库（12 族）

> 这里的"原理来源"是 E1/E2（TLOU2 设计师原话/可观测分析）；**所有参数是本项目 E3**，见附录 A。
> 选机制时**不是越多越好**：一关 6–12 条，每族最多出现 2 次，重复第二次必须换参数。

| # | 族 | 玩家动词 | 代价 | 读法（无 UI） | 断言 |
|---|---|---|---|---|---|
| 1 | **Traversal 通行** | 翻/爬/挤/伏/跳/降 | 暴露时间、噪声 | 高度带 + 磨损面 | 净高落在带内、落点 ≥0.80 m |
| 2 | **Cover 掩护** | 贴/蹲/探头/转移 | 机动性、被绕后 | 半身/全身两档 | 高度在带内、簇间距合理 |
| 3 | **Sightline 视线** | 看/绕/断视线 | 路程 | 断点节奏 | 每 `LV-SIGHT-BREAK` 一处 |
| 4 | **Gate 门禁** | 开/撬/解码/绕 | 时间、噪声、资源 | 门态 + 锁具 | 硬门禁只出现在撤离点 |
| 5 | **Vertical 垂直** | 攀上/俯视/跳下 | 高处暴露、回程 | 抓手/落点 | 每 climb 配一条下沉路 |
| 6 | **Stealth 潜行** | 蹲/伏/入草/下水 | 速度 | 遮挡密度 | 遮挡覆盖 ≥70% |
| 7 | **Lure 诱导** | 跟随/查看 | 偏离主线 | 光/声/形 | 每个诱饵指向下一目标 |
| 8 | **EmptyThreat 空威胁** | 警戒/绕行/试探 | 时间、心理 | 战斗语法密度 | 无 AI、但掩体齐；反应率 ≥40% |
| 9 | **Frontline 前线** | 穿越/压制/包抄 | 血量、弹药 | 空旷脆弱带 | 视野内敌掩体 ≤3、焦点可见 |
| 10 | **Pacing 节奏** | 等/走/冲 | 时间 | 光线与声景 | tempo 曲线有峰有谷 |
| 11 | **Extraction 撤离** | 接近/等待/登机 | 全部 | 撤离点视觉锚 | 最后 150–200 m 仅步行 |
| 12 | **Streaming 流送** | （玩家无感） | — | — | 接驳口袋即预载点 |

### 3.1 详解卡 A：空威胁（EmptyThreat）——本项目最该抄的一招

**原理（E1）**：博物馆侧厅一个敌人都没有，但 Hill 照样摆了掩体、可制作物、完整的战斗空间语法。测试者进去后**真的开始变谨慎**。他的原话大意：我不是在控制玩家，而是在指引。

**为什么适合你**：撤离游戏最贵的是"不确定"。空威胁让玩家被自己的条件反射吓到，**零 AI 成本**产出紧张感；同时它天然制造 PvPvE 的"这里刚才有人吗"。

**参数**：

| 参数 | 值 | E | 说明 |
|---|---|---|---|
| `aiCount` | 0 | — | 硬性为 0，禁止偷偷刷怪 |
| `coverClusters` | 4–6 / 200 m² | E3 | 与真实战斗区同密度，否则读不出来 |
| `combatGrammar` | `full` | — | 掩体 + 可破坏 + 血迹 + 弹壳 + 破窗 |
| `escapeHatch` | ≥1 | E3 | 必须有"其实能跑掉"的路，否则是骗 |
| 触发率 | ≥40% | E3 | 12 名测试者中无提示蹲/瞄的人数占比 |

**三条红线**：
1. **不能骗命**：玩家在里面死了（比如被别的队伍伏击）会归因于"这游戏在耍我"。所以空威胁区必须**真的可以安全通过**。
2. **不能重复用**：同一关最多 1 处，且不能放在撤离点前——那会变成"狼来了"。
3. **必须有出口**：`escapeHatch` 缺失会变成纯粹的焦虑，而不是紧张。

### 3.2 详解卡 B：前线与焦点（Frontline / Focus)

**原理（E2，Teletype 逐帧分析 + Barclay 词汇表）**：
- **焦点（Focus）**= 短期目标，要能**透过敌方防线看见**（一帧里同时看到"我要去哪"和"谁挡着我"）。
- **前线（Frontline）**= 双方掩体之间那片空而脆弱的区域。它的存在让玩家必须算"什么时候冲"。

**参数**：

| 参数 | 值 | E |
|---|---|---|
| 视野内可见敌方掩体簇 | ≤3 | E3 |
| 焦点可见性 | 从每个进入点至少 1 个方向可见 | E3 |
| 前线宽度 | 6–12 m | E3 |
| 侧翼通路 | ≥1 条不与前线重叠 | E3 |

**断言**：从每个 `entry` 点做 3 条射线（左/中/右），至少 1 条命中 `focus_marker`；否则焦点不可读，返工。

### 3.3 详解卡 C：面包屑链（Lure / Breadcrumb）

**原理（E1，Barclay）**：受《福尔摩斯》与《Her Story》启发——每条线索**指向下一条的位置**，可以任意顺序拾取，最终**把玩家带回主线**（顺带解决迷路）。

**规则**：

| 规则 | 值 | 说明 |
|---|---|---|
| 链长 | 3–5 环 | 超过 5 环玩家记不住 |
| 指向方式 | 文本 + 空间双保险 | 笔记写"在 Barko's"，同时用光照/声音暗示 |
| 任意顺序 | 必须成立 | 拾取顺序不影响可达性 |
| 回主线 | 最后一环必须注入关键路径 | 否则玩家永远在支线 |
| 密度 | 服务巷每 25 m ≥1 | 对应 GDD §7 线索系统 |

**断言**：随机打乱拾取顺序 100 次，100 次都能在 90 s 内回到主线；断链率必须为 0。

### 3.4 详解卡 D：接驳口袋（Streaming 兼战术）

**原理（E1，Barclay 的 Valve / E3 你的地图文档）**：Valve 是连接两个区域的走廊，作用是**把上一个区域流送出去、下一个流送进来**。你的"接驳口袋"正好是同一个东西，外加战术功能。

**四合一验收**（来自 [地图设计-西雅图裂城-v1.0.md](./地图设计-西雅图裂城-v1.0.md) §3.3）：

1. 载具可短暂停留，不挡主路（宽 4–6 m）。
2. 进入肌理层有 **≥3 个方向**出口。
3. 本身是低掩体密集区（0.90–1.10 m）。
4. 必有一条"上高处"路径（车顶 → 雨棚 → 二层窗，两段 1.20 m）。

**断言**：以上四条 + `preload_volume` 覆盖口袋 → 街区。

### 4.1 `level_<id>.jsonc`

```jsonc
{

  "levelId": "sea_downtown_poi_03",
  "layer": "L2",                          // L0..L4，对齐地图设计 v1.0 §1

  "theme": "看得见拿不着",                 // razor：一句话主题
  "goals": {

    "experience": "低速、可反复穿行、随时能撤",

  },
  "arc": [
    { "act": 1, "intent": "setup",   "tempo": 0.20, "durationS": [90, 150] },
    { "act": 2, "intent": "develop", "tempo": 0.55, "durationS": [120, 240] },
    { "act": 3, "intent": "turn",    "tempo": 0.85, "durationS": [60, 120] }
  ],
```

### 4.2 校验器必须实现的 12 条断言

1. 每条 `mechanism` 四要素齐全（`verb`/`cost`/`read`/`acceptance`），缺一 `throw`。
2. `family` ∈ §3 的 12 族枚举。
3. `cost.type` ∈ `time | noise | exposure | resource | irreversibility`。
4. `read.noUi === true` 时 `read.telegraph` 不得为空；`false` 时必须给 UI 理由字段。
5. `traversal` / `cover` 类的 `space.prefab` 必须存在于 prefab 清单。
6. 掩体高度 ∈ `[LV-COVER-LOW] ∪ [LV-COVER-HIGH]`；落在 `LV-COVER-GAP` 内直接拒绝。
7. `traversal` 净宽 ≥ `LV-CLEAR-W`；落点净空 ≥ 0.80 m。
8. `arc` 的 `tempo`：`max ≥ 0.75` 且 `min ≤ 0.35`。
9. `graph.edgeDisjointPaths ≥ 3`（入口 → 焦点的边不相交路径）。
10. `hasBackgate === false`；每个 `drop` 在 `LV-DROP-RETURN` 内提供回程边。
11. 每个 POI ≥1 个 `vantage`，且带 `overview/observe/plan/execute/reward` 五个标记。
12. `budget` 三项不得超：`tri ≤ 350000`、`interactables ≤ 25`、`vehicles ≤ 6`。

### 4.3 枚举

- `family`: `traversal | cover | sightline | gate | vertical | stealth | lure | empty_threat | frontline | pacing | extraction | streaming`
- `cost.type`: `time | noise | exposure | resource | irreversibility`
- `read.channel`: `height_band | cover_density | light | sound | silhouette | texture_wear | door_state`
- `act.intent`: `setup | develop | turn | resolution`

## 5. 验收

### 5.1 机器可判（跑校验器 + 图算法）

| # | 项 | 判定 |
|---|---|---|
| A1 | 图连通 | 删除任一条**单边**后仍连通 |
| A2 | 三条路 | 至少 1 潜行、1 垂直、1 快速撤退，互不重叠 |
| A3 | 掩体带 | 无 `(1.10, 1.60)` 区间物件 |
| A4 | 视线断点 | 沿主路径采样，间距 ∈ `LV-SIGHT-BREAK` 的点 ≥80% |
| A5 | 无 backgate | 无单向门；每个 drop 有回程 |
| A6 | 预算 | 三项达标 |
| A7 | 撤离 | 最后 `LV-WALK-LAST` 段标记 `V0`（仅步行） |

### 5.2 人可判（5 项，每项 5–12 人）

| # | 测试 | 通过标准 |
|---|---|---|
| H1 | **盲测导航**：进入 POI 不给提示，问"你打算往哪走、为什么" | ≥4/5 命中设计意图，且理由来自空间（不是 UI） |
| H2 | **空威胁**：观察是否无提示警戒 | ≥40% 触发 |
| H3 | **线索乱序**：打乱面包屑顺序 | 100% 能回主线 |
| H4 | **失败前进**：被逼到角落 | 存在 ≥1 条退路，且玩家能找到 |
| H5 | **撤离可读**：站在最后一个 vantage 上 | 能指出"撤离点大概在哪个方向" |

### 5.3 三种结论，只有三种

| 结论 | 条件 | 动作 |
|---|---|---|
| **通过** | 5.1 全绿 + 5.2 达标 | 进 M6 |
| **返工** | 断言红，但机制本身成立 | 只改参数，不改拓扑 |
| **砍掉** | M5 后仍无断言或从未触发 | **删**，不留"以后再说" |

## 6. 失败模式处方（20 条）

| 症状 | 成因 | 处方 |
|---|---|---|
| 玩家永远走同一条路 | 三条路同宽、同亮、同材质 | 差异化：潜行路暗而窄、垂直路亮而有抓手、撤退路宽而有载具 |
| 玩家不蹲 | 掩体高度不收敛，或中间带放了物件 | 归并到两档，清空 `(1.10,1.60)` |
| 房间很多但都一个样 | 缺视觉语言分级 | 每 POI 一个 hero prop + 一个 weenie |
| 空房间没有紧张感 | 只放了"敌人位置"，没放战斗语法 | 加掩体簇 + 可破坏 + 血迹 + 破窗 |
| 玩家被逼死角 | 无 fallback 路 | 每个掩体簇 ≥1 条后退通道 |
| 迷路 | 面包屑断链 | 每条线索指向下一条，最后一环回主线 |
| 关卡变"清单式搜刮" | P3 间距 <8 m 且无遮挡 | 强制每相邻 P3 一处视线断点 |
| 撤离点被单点堵死 | 只有一个候选位 | ≥2 个候选位 + ≥3 条进路 |
| 车能开到撤离点 | 没做 `V0` 段 | 最后 150–200 m 强制步行 |
| 爬上去下不来 | 只做上不做下 | 每个 climb 配 drop 或绳索 |
| 全程紧张到麻木 | tempo 全 >0.7 | 强制插入谷值 ≤0.35 的喘息段 |
| 玩家看不懂线索 | 全是文字 | 光/形/声优先，文字兜底 |
| AI 卡在掩体 | 绕行 <0.80 m | 掩体四周留绕行 |
| 门后突然空荡 | 没有"门后预载" | 接驳口袋做 preload volume |
| 迭代停不下来 | blockout 做得太细 | 回到"扔掉会心疼"红线，砍细节 |
| 美术进场后大改 | 没锁布局 | greybox gate 前必须冻结拓扑 |
| 掩体看着能挡却被穿透 | 承诺不一致 | 视觉体积 = 碰撞体积 |
| 战斗碗太小学不会绕圈 | 直径 <18 m | 扩到 `LV-BOWL-D` 区间 |
| 视角到处穿墙 | 相机没参与白盒走位 | 白盒阶段就用最终相机 |
| 测试者说"挺好"却没有数据 | 问了主观题 | 改问"你刚才为什么停下" |

### 7.2 三条制作纪律

1. **"如果你觉得扔掉会心疼，说明你已经走太远。"**（Barclay）——blockout 的唯一目的就是被扔掉。
2. **blockout 是唯一能大改的时机。** greybox 之后只能"有意义的修改"。
3. **始终保持第一眼 vista 不变。**（Barclay 做市中心时，所有迭代都不动入口那段全景）——它是关卡的"身份证"。

### 8.2 ⚠️ 两处必须先解决的冲突（不解决，白盒必翻车）

**冲突 1：蹲姿胶囊 vs 匍匐/车底净高**

- `00 §4` 的 `CC-CROUCH-H = 1.05 m`（胶囊总高）。
- 交互物清单要求：匍匐净高 0.55–0.75 m（TR-12）、车底净高 0.35–0.45 m（HD-02）。
- **结论：0.35–0.75 m 的洞，用 1.05 m 的蹲姿胶囊过不去。** 必须新增**匍匐胶囊**（建议 `LV-PRONE-H = 0.55 m`，E3），否则 HD-02 / TR-12 在本项目**不可实现**。
- 这是"抄尺寸不看胶囊"的典型事故：网上量到的洞高是对的，但你的角色进不去。

**冲突 2：REA 的身高 vs 00 的胶囊**

- REA §3.1 用 1.80 m 身高、0.85–0.95 m 蹲高（**身体**高）。
- `00 §4` 用 1.78 m、`CC-CROUCH-H = 1.05`（**胶囊**高）。
- **结论：两套口径都对，但不可混用。** 本文一律用 `00` 的胶囊口径；引用 REA 的米数时必须注明"身体高"。

**一句话总结**

> **先问"让玩家演什么"，再问"他凭什么读得懂"，最后才问"空间长什么样"；每条机制都要能被一句断言判死；用 2 天做出能跑的糙版，然后扔掉、重做、再扔掉，直到第一眼 vista 和那条断言同时成立。**
